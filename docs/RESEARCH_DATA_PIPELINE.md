# INDB to baseline dietary memory

1. Preserve the original workbook in restricted source storage. Run the importer with an explicit path. `INDB.xlsx` supplied for this project matches the stated 1,014 × 82 data structure; filename alone is not a dataset version.
2. Importer v2 hashes the original bytes, validates exact mappings, retains original codes, and writes deterministic sorted output. Its version is `indb-<first 16 SHA-256 characters>-serving-v2`; the report also stores the full SHA-256. Store report and raw file together. Byte-identical inputs produce identical outputs.
3. Required serving nutrients are energy_kcal, protein_g, carb_g, fat_g, fibre_g, sodium_mg, each sourced exclusively from the same `unit_serving_*` basis. Per-serving zero is valid. Missing/negative/non-finite values or absent unit labels exclude the row with reasons. The original primarysource is retained internally.
4. Unit text is a household label, not measured grams. All serving weights are null/blank. Do not infer gram weights from a ratio of nutrient columns or from numeric-looking label text. Unqualified original columns are intentionally not mixed into this catalog.
5. Preserve the named versioned JSON/CSV snapshots. The unversioned filenames are current convenience copies. Before enabling a new catalog, archive its report and exclusions, deploy its search catalog, and update the server policy catalogVersion. Old drafts are rejected for review if versions differ. Use the matching versioned CSV for historical exports.
6. The public catalog includes recipe name, aliases, code, and serving unit only. Parenthetical names and grounded synonym groups expand search suggestions; they never collapse or equate nutritionally different recipes. No serving values or new nutrition are invented.
7. Export with the local Admin SDK tool. Malformed records are quarantined in export_errors.csv. CSV formula-like strings are prefixed with an apostrophe for spreadsheet safety. Retain that distinction if doing textual re-mapping; codes are unaffected.
8. Join INDB entries on **catalog_version + food_code**. Also verify recipe name and serving unit before multiplying quantity by per-serving nutrients. `join_nutrition.py` emits per-entry values only for verified joins. It never supplies nutrient values for custom/unmatched entries.
9. The MOO project may consume participant variables plus the resulting nutrient logs as baseline memory for NSGA-II, NSGA-III, MOEA/D, SPEA2, MOPSO and APPO. Aggregate by response only after identifying incomplete days and unresolved custom foods. A sum of known entries is not automatically a complete day total.

The sex field supports the dissertation's existing sex-specific nutritional calculation. Its two response categories are not a comprehensive measure of gender identity. Preserve its stated purpose in methods and limitations. Ages 16–17 require approved assent/guardian consent and should be tracked by their document versions; this website does not decide ethical eligibility or derive adult metabolic equations for minors.

Current reconciliation: 917 included + 97 excluded = 1,014 records. Earlier pilot counts were approximate and do not justify removing valid rows. All source columns remain untouched in the source workbook.
